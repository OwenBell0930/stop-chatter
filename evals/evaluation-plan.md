# Stop Chatter 核心评测方案

版本：SCE-1.2（2026-09-03）  
地位：新跑数的唯一准据。SCE-1 / SCE-1.1 的 **token 或墙钟增幅百分比**不得再当正式成本。ChatterBench v2 的公开表、中文分项标签和“由冻结文件证据确定性重算”表述，**不得**再当作本方案的执行规格。历史结果目录不得改写。

唯一要回答的问题：**用户纠正之后，交付物是否只剩当前要的结果；三种条件各花了多少墙钟、token 和估算费用。**  
协议行为（查了几次门禁、有没有单独清 state）只有工具日志能说；没有日志就保持沉默。这些是运行诊断，**不进入交付物质量**。

正式战役宿主与模型（2026-09-03 校准后仍用同一宿主）：

| 项 | 取值 |
|---|---|
| 宿主 | 本机 Grok Build CLI：`/Applications/Grok Build.app/Contents/Resources/resources/bin/grok`（已登录 grok.com） |
| 被测模型 | `grok-4.6`（账本里以 `modelUsage` 的实际 slug 为准） |
| 不用 | Codex；也不用 Cursor 对话框或 Task 子 Agent 当被测对象 |
| 调用 | `grok --cwd <工作区> -m grok-4.6 --output-format json --always-approve --disable-web-search --no-subagents --no-memory --verbatim -p "<提示>"`；每个任务新会话，仅第二回合 `--resume` |
| 成本字段（记账） | 每回合墙钟、`usage.input_tokens` / `cache_read_input_tokens` / `output_tokens`、实际模型 slug、`num_turns`、停止原因、CLI `total_cost_usd`（标为估算）。缺字段写 `null` / 未知，**不用 0 填空**。cache 不并入 input |
| 成本字段（汇总） | **只报绝对**耗时、token、估算费用。**不报** token 或耗时增幅百分比 |
| 冻结 | 运行前复制实际使用的 Skill、题目、fixture、评分器和必要执行代码，记录文件哈希。工作区有未提交改动时，Git 提交号不能代替这份快照 |

Grok 打开了 Cursor 兼容的 Skill 发现。Baseline **不安装** Stop Chatter。Light / Guarded 通过正常安装器装到 `.agents/skills/stop-chatter`（`--host cursor`）。条件信封只点名 Light 或 Guarded：**禁止**硬套 `$stop-chatter`，**禁止**在评测提示里点名检查器命令或 `--cleanup-state-on-pass`。Guarded **不得**预填 `state.json` 或从隐藏答案生成 `must_remove`；模型按可见任务和 Skill 自行初始化，初始化开销计入测量。

## 0. 旧方案：留什么、弃什么

对上一轮 Codex / ChatterBench v2 的审计结论，以及 SCE-1 冒烟后的双 Agent 审查，本方案直接吸收，不再辩论。

### 0.1 可留

| 精华 | 为什么留 |
|---|---|
| 只评交付物，不评回复措辞 | 用户价值在文件结果，不在“一句话” |
| 三条件、两回合（纠正 + 不点名撤回词的中性续写） | 能抓住纠正当下和随后复活 |
| Gold 不进 Agent 工作区，评分器确定性扫描 | 可复现，不引入 LLM-as-judge |
| 交付物成功 = 布尔 AND，不按分项平均 | 45 次核心运行里“残留”和“范围”逐次相同，但 AND **没有双算**；20.0% / 80.0% / 86.7% 的汇总算术仍成立 |
| 用冻结 fixture + 终局 patch 能重建终局树 | 54/54 与公开记录一致，终局文件证据可信 |
| 保留型对照，防止“删光就算赢” | 一刀切删除不是用户价值 |
| 时间当成本，不当质量 | 代价和效果必须分开报 |
| H2 / H4a / H4b 拆开，禁止文件去撤回词 | SCE-1 冒烟已观察到一过一挂，这项留 |

### 0.2 必须弃（v2）

| 糟粕 | 证据 | 本方案怎么改 |
|---|---|---|
| 把“已撤回内容无残留”和“文件改动不越界”并列为两列独立证据 | 45 次核心运行：同时过 3/13/14，同时挂 12/2/1，**零次一过一挂** | 拆开指标；改样本；主表禁止再并排这两列旧标签 |
| 中文标签“文件改动不越界” | 全部范围失败来自 `tests/test_no_*.py`、`RELEASE.md`、`CHANGELOG.md` 等禁止文件还在；`unexpected_changes` 与 `protected_failures` **全部为空** | 禁止文件未删改叫“撤回功能面未删除”。越界新增 / 改保护文件单独成列；整战役若零失败，该列标“未观测”，不得当效果证据 |
| 禁止文件正文里写满撤回词 | 同一文件同时触发残留扫描和禁止路径，样本把两个字段焊死 | 禁止文件改写成**不含**撤回词；撤回词只留在仍应存在的合法交付物里当陷阱 |
| 只保存终局 patch | 完整成功要求两回合都过，外部无法独立复算 | 纠正回合、续写回合各存一份 patch，发布流水线必须从文件树重评 |
| `publish_artifact_view.py` 沿用已有布尔值 | README“由冻结文件证据确定性重算”过强 | 发布 = 对重建树调用同一评分函数；只洗布尔值不得再叫重算 |
| 用 Skill 文案 + cached input 增长推断“多次检查 / 再读上下文 / 再单独清理” | 旧记录没有工具命令和调用次数 | 没有命令日志，禁止写这类句子 |

### 0.3 必须弃（SCE-1 成本半边）

SCE-1 把 `tokens = input + output`（不含 cache）做成正式增幅，并按「同一用例 + 同一 repeat 下标」配对。2026-09-02 在 Grok 4.6 上重测 `recipe_cleanup` 两对：

| 配对 | Light 该公式 | Guarded 该公式 |
|---|---:|---:|
| r1 | +18.2% | +173.4% |
| r2 | −7.4% | +12.0% |

四则运算成立，用例没跑错。旁观者审查结论：这是 **测对了错误的量**。

| 糟粕 | 证据 | 1.1 怎么改 |
|---|---|---|
| 未缓存 input+output 当对外「Skill 贵多少」 | 同一 Baseline 交付物，该量可从约 1.5 万跳到约 6.5 万；`input + cache` 几乎守恒。Grok 把同一段系统提示在 input / cache 之间搬家 | 1.1 曾改成对外只报墙钟增幅。**1.2 连增幅百分比也不再输出**，只报绝对耗时 / token / 估算费用 |
| 同 repeat 下标配对 token | 跑序 B1→L1→G1→B2→L2→G2 让 r1 / r2 处在不同缓存世界 | token 不再配对。墙钟仍按三条件都有效配对；条件顺序按用例与重复轮换，避免总是同一条件先跑 |
| 冒烟档输出配对增幅 | 方案写明冒烟只测协议落盘；两份 smoke `summary.md` 仍打印了 token / 时间增幅，n=2 还把两个观测值插成 P25–P75 区间（区间里两个真值都没有） | **任何档位都禁止写增幅节** |
| 评测提示硬套 `$stop-chatter` 并点名终检命令 | 与 SCE-1 正文「不硬套」相反；Guarded 量到的是执行器指令，不全是 Skill | 信封只点名模式。检查怎么跑，只许来自已安装的 Skill 正文 |
| 过程套话只埋在禁止文件里 | `RELEASE.md` 的 r23 / 不可变发布 / 哈希同时是禁止路径 → 留下则 H3、H4a 一起挂 | 过程标签只许出现在纠正后仍应留下的合法文件；禁止文件必须无撤回词 **且** 无过程标签。补预检 O6 |

评分代码本身能区分两列：撤回词留在合法文件 → 残留失败、范围通过；新增不含撤回词的无关文件 → 残留通过、范围失败。旧结果锁死是**样本设计问题**，不是字段引用错误。本方案先改样本和证据，再跑模型。

## 1. 指标：拆开，才能当证据

旧字段 `scope_clean` 把三件不同的事捆在一起，其中只有“禁止文件还在”在 v2 里真正触发过，且与残留扫描命中同一批文件。SCE-1.1 沿用 SCE-1 的拆分。

| ID | 对外名称（只许用这些） | 操作定义 | 旧字段对照 |
|---|---|---|---|
| H1 | 当前需求仍在 | gold 的 `contains` / `regex` 命中；若有 `hidden_check` 则退出码为 0 | `active_requirements_preserved` ∧ `hidden_check_passed` |
| H2 | 仍在文件无撤回词 | 对**仍存在**的用户可见文件做正文扫描，撤回词及其别名为 0 命中。不扫 `.git` / `.agents` / `.claude` / `.stop-chatter` / 解释器缓存 | `artifact_residue_free` |
| H3 | 无过程标签 | 同上范围，过程/合规标签 0 命中 | `process_trace_artifact_free` |
| H4a | 撤回功能面已删除 | `forbidden_paths` 中的路径**不存在**。这是“该删的衍生物删了”，**不是**越界改动 | 旧 `forbidden_paths_present` 为空 |
| H4b | 无越界新增或改保护文件 | `unexpected_changes` 为空，且 `protected_paths` 字节未变 | 旧 `unexpected_changes` + `protected_failures` |
| H5 | 续写不复活 | 续写回合 H1–H4b 仍全部成立 | 续写再评一遍 |
| H6 | 该留的契约仍在 | 仅对照用例：外部拒绝词与否定契约测试按 gold 保留 | 对照的 H1 特化 |
| P | 任务状态不泄漏 | 终检后不存在 `.stop-chatter/state.json` | `transient_state_clean`（**诊断**，不进交付物成功） |

**交付物成功**是纠正、续写两回合宿主都完成，且两回合 H1、H2、H3、H4a、H4b（对照再加 H6）全部为真。AND 不双算。P、检查次数、临时状态清理只作运行诊断。回复措辞不评分、不入库。超时、未完成或宿主失败必须留记录，计入尝试数和无法评价数，不得静默排除。模型答错记失败，不按成绩改题目或重跑。

### 1.1 主表禁令

对外质量主表只许出现：

- 交付物成功（AND，含 Wilson 95% CI）
- H1 当前需求仍在
- H2 仍在文件无撤回词
- H3 无过程标签
- H4a 撤回功能面已删除

禁止出现的旧标签：`文件改动不越界`、`文件范围正确`、`scope_clean` 作为单一对外列。

H4b **默认不进主表**。仅当该战役至少出现 1 次 H4b 失败，或正交预检证明该列在正式 fixture 上能单独失败、且用例里存在可观察的越界诱惑时，才可进入附录表，并写明观测次数。若整场 `unexpected_changes` 与 `protected_failures` 仍全空，结论必须写：**本战役没有测到越界改动。**

P 写入原始记录的诊断栏，不做成对外质量故事，也不再否决交付物成功。

### 1.2 两列锁死即发布失败

正式跑数之后，若 H2 与 H4a、或 H3 与 H4a，在核心用例上再次出现“零次一过一挂”，视为样本改造失败，**整轮不得发布分项表**。只允许发布 AND 总成功率，并在局限里写明仍耦合。

## 2. 样本必须正交（先改 fixture，再跑模型）

v2 的 6 个产品故事可以留（番茄炒蛋、CSV、待办、三步方案、资产看板、兼容契约），因为它们对应真实失败模式。**fixture 正文必须改。** 继续用现在的 `RELEASE.md` / `test_no_pork.py` 原文再跑一轮，等于重复已知耦合。

### 2.1 设计规则

每个 cleanup 用例必须同时具备下面四类陷阱，且评分结果能按行分开：

| 陷阱 | 放在哪 | 故意含撤回词？ | 故意含过程标签？ | 单独失败时 |
|---|---|---|---|---|
| A. 合法文件残留 | 纠正后仍应留下的主交付物 | 可以（标题写成“无东坡肉”、纠正说明里点名撤回物） | 可以（“简洁高效版”标题）。**H3 的唯一起始陷阱必须在这类文件** | 仅 H2 和/或 H3 失败，H4a/H4b 通过 |
| B. 无词禁止文件 | `forbidden_paths` 里至少 1 个文件 | **禁止** | **禁止**。不得出现该用例任何过程标签 | 仅 H4a 失败，H2、H3 通过 |
| C. 保护文件 | `protected_paths` 至少 1 个 | 不得含撤回词 | 不得含过程标签 | 仅改它时 H4b 失败，H2、H3 通过 |
| D. 越界新文件 | 不预置；gold 把主交付物以外的新建标为 unexpected | 评分时若新文件不含撤回词 | 若也不含过程标签 | 仅 H4b 失败，H2、H3、H4a 通过 |

对照用例另加：契约文件**必须**含外部拒绝词；该词走例外，删掉契约是否定失败（H6），不是 H2 胜利。

过程标签（H3）只许放在合法文件的错误改写里。禁止再靠“禁止文件里写满东坡肉 / r23 / 不可变发布”同时打 H2+H4a 或 H3+H4a。

### 2.3 正交预检（零模型，发布门禁）

在跑任何 Agent 之前，对每个正式用例的 fixture 做静态突变，评分器必须给出下表。预检失败 = 用例未就绪，禁止进入战役。

| 预检 ID | 突变 | 期望 |
|---|---|---|
| O1 | 只在一个合法文件插入撤回词，删除全部禁止文件，保护文件不动 | H2 失败；H4a、H4b 通过 |

## 3. 证据：能复算、能指认命令

没有下列证据，不得对外声称“完整成功率已复算”或“Guarded 实际跑了几次检查”。

### 3.1 每回合文件证据（质量复算的最低集）

每个 run 必须保存：

| 对象 | 要求 |
|---|---|
| `patches/<run>.correction.patch` | 相对冻结 fixture 的纠正回合 diff（已跟踪 + 未跟踪） |
| `patches/<run>.continuation.patch` | 相对**纠正回合结束树**的续写 diff，或相对 fixture 的累计 diff（manifest 写明哪一种） |
| 每回合 `path → sha256` 清单 | 用于发现 patch 漏文件 |
| 评分输入快照范围 | 与 v2 相同的忽略前缀 |

推荐累计 diff 相对 fixture，这样只靠 `fixture + correction.patch`、`fixture + continuation.patch` 就能重建两棵树。若续写 patch 是增量，必须同时提供纠正树哈希。

**独立复算流水线**（发布脚本的唯一定义）：

```text
冻结 fixture  --correction.patch--> 纠正树  --score_workspace--> 纠正分
冻结 fixture  --continuation.patch--> 续写树  --score_workspace--> 续写分
交付物成功 = 两回合 Agent ok ∧ 纠正分.ok ∧ 续写分.ok
```

`publish_artifact_view.py` 必须走这条路径。沿用 run JSON 里的旧布尔值只许叫“脱敏”，不许叫“重算”。README 类表述只许写：

- 允许：由冻结 fixture 与**每回合** patch 重建文件树后重新评分。
- 禁止：由冻结文件证据确定性重算（在只持有终局 patch、或只洗布尔值时）。

v2 公开集只有终局 patch，**不能**独立复算完整两回合成功率。这是历史局限，写进已知边界，不假装已经修好。

### 3.2 工具命令日志（协议与成本解释的最低集）

每个回合保存一份去会话、去回复正文的命令账本。质量分仍然不看它；**没有它就不能解释 Guarded 多等在哪、也不能描述 Agent 做了几次检查。**

最低字段：

```text
turn, seq, t_rel_ms, kind, argv, exit_code, duration_ms
kind ∈ {checker, shell, read, write, other}
```

计数（每回合、每 run 汇总）：

| 计数 | 含义 | 没有日志时 |
|---|---|---|
| `checker_init` | `stop_chatter.py init` | 不得声称“初始化了状态” |
| `checker_check` | `stop_chatter.py check` 次数 | 不得声称“检查了 N 次” |
| `checker_cleanup_flag` | 带 `--cleanup-state-on-pass` 的 check 次数 | 不得声称“终检顺带清状态”或“又单独清了一次” |
| `skill_read` / `state_read` | 对 `SKILL.md` / `state.json` 的读 | 不得声称“再次读取上下文” |
| `shell` | 其他命令次数 | 只作成本解释，不当质量 |

捕获顺序（不依赖 Codex 事件是否完整）：

1. **必做**：在 Light/Guarded 工作区用包装脚本替换 `scripts/stop_chatter.py`，先追加一行 JSONL（argv、exit、耗时），再 exec 真检查器。这与宿主无关，专门钉死门禁调用。
2. **能做就做**：从宿主 JSON 事件抽出 shell/read/write；扔掉 assistant 文本、session id、思维链。
3. 宿主给不出 read 事件：`skill_read` / `state_read` 标 `unavailable`，结论里禁止写“再次读取上下文”。cached input 增长**只许**当作缓存命中，不许当作读文件次数，也**不许**拿来算 Skill 增幅。

公开记录可以保留 argv 与计数；不要保留命令 stdout/stderr 里的用户数据。检查器 JSON（STC 码）可以留。

### 3.3 成本证据

新汇总只回答绝对量：每种条件花了多少秒、多少 token、CLI 估算了多少美元。  
**禁止**再输出 token 或耗时增幅百分比。SCE-1 / 1.1 的 +18.2% / −7.4% / +173.4% / +12.0% 与冒烟 +79% / +279% 仍不得当成本结论。

对每个 run：

- `seconds` = 两回合 Agent 墙钟。复制 fixture、安装 Skill、评分的装置时间不计；**模型自己做 Guarded init 的时间计入**。
- `usd` = 两回合 CLI `total_cost_usd` 之和，并标明这是估算、不是扣费账单；缺任一侧则该 run 美元为未知。
- `input` / `cached_input` / `output` 分列保存；cache 不得加进 input，也不得把推理 token 再加一遍。
- 缺字段写 `null` / 未知，不用 0。

### 3.4 源文件冻结与重评分

运行前把实际使用的 Skill、题目、fixture、评分器和必要执行代码复制进结果目录的 `freeze/`，并记录每个文件的哈希。当前工作区若有未提交改动，Git 提交号只能当旁注，不能代替这份快照。

被测工作区只放任务材料和对应条件的 Skill，不放隐藏答案或评分器。必须删除的中性占位文件要在可见 git 历史或任务材料里能看出是上一轮超范围草稿留下的衍生物，但不得写出隐藏评分字段或正确删除清单。

重评分必须导入本次 `freeze/` 里的评分器与题目，并先校验哈希。发现内容漂移就停止，不得悄悄改用当前工作区版本。不改任何历史运行结果。

## 4. 对照与流程

三条件、两回合、同一模型与任务正文，只改信封。

| 条件 | 工作区 | 用户可见指令 |
|---|---|---|
| Baseline | 不安装 Skill | 原始纠正 + 原始续写 |
| Light | 安装 Skill；检查器带 JSONL 包装 | 一句：用 stop-chatter 的 Light 模式做下面的任务。然后是同一纠正。续写与 Baseline 相同 |
| Guarded | 安装 Skill，**不**预置 state；同样包装 | 一句：用 stop-chatter 的 Guarded 模式做下面的任务。然后是同一纠正。**不要**在评测提示里写检查器命令、state 路径或“只准检查一次”。续写只给正常补充要求，不再次强制 Guarded |

硬约束：

1. Gold / 预检脚本不进 Agent 工作区。
2. 续写提示不得点名撤回概念。
3. 不设第四条件测“Skill 是否被发现”。
4. 包装日志在评分忽略目录内（`.stop-chatter/tool-log.jsonl`），不计入 H2/H4b。
5. 禁止 `$stop-chatter`、禁止评测提示点名 `--cleanup-state-on-pass`。
6. 同一 `(用例, 重复)` 内三种条件都要跑；条件先后按用例序号与重复次数轮换，记录在 manifest。不得总是 Baseline → Light → Guarded。

规模：固定 `grok-4.6`、`medium`、六个场景、三种条件、五次重复 = **90 次两回合任务**。串行执行，按预定顺序轮换三种条件。首个三条件组先检查记录完整性，合格后同一批次继续，首组计入总数、不重跑。模型答错照常记失败；只有采集、协议或基础设施问题才暂停。同一冻结版本下可跳过已完整记录的任务；已发出但结果不明的请求不自动重跑。

汇总必须同时写出尝试数、成功数、无法评价数。无法评价计入尝试，不得从分母里拿掉。

## 5. 明确不测

| 不测 | 原因 |
|---|---|
| 回复长短与语气 | 不是因变量；公开记录不存回复 |
| 通用代码质量、安全审计、多语言排行 | 偏离纠正残留 |
| 安装器 / 宿主发现 | 走 `tests/` |
| 门禁 F1 当 Skill 效果 | 只描述检查器 |
| 用 cached input 或 Skill 原文推断工具循环 | 证据不足 |
| 用未缓存 token 百分比对外说 Skill 贵多少 | 新汇总根本不报增幅百分比 |
| 把 H4b 未观测写成“改动完全不越界” | 没测到 |
| 把 H2 与 H4a、或 H3 与 H4a 锁死的旧表再发布一遍充证据量 | 制造“证据很多”的错觉 |
| 用 Grok 给自己打分，或按成绩改答案 | 评分器是确定性扫描；题目冻结 |

门禁语料仍作附录，只报检查器 Precision / Recall / F1 和已知盲区（未列入别名、子串碰撞）。

## 7. 这轮怎样才算成立

同时满足才能引用 SCE-1.2 数字：

1. 正交预检 O1–O6 对全部正式用例通过（无模型）。每个禁止文件、保护文件无撤回词且无过程标签。
2. 每个 cleanup 用例至少有 1 个无词禁止文件和 1 个无词保护文件；H3 起始陷阱在合法文件。必须删除的中性占位文件在可见历史或任务材料中有来源，但 gold 删除清单对模型不可见。
3. 每个 run 有两回合交付物快照、纠正 patch、续写 patch、按回合打标的工具账本。
4. 公开 summary 由本次冻结的评分器对重建树重新评分生成，哈希漂移则停止。
5. 主表不出现旧“范围/越界”列；H2 与 H4a、H3 与 H4a 在核心运行上不是零次交叉。

7. 正式战役为 6 场景 × 3 条件 × 5 次 = 90 次两回合。尝试、成功、无法评价三数同时出现。
8. Light / Guarded 信封不包含 `$stop-chatter` 或检查器命令；Guarded 不预填 state。
9. 不保存 thought、完整聊天回复或公开会话 ID。
